Deep dive

How I built Sulhafa

01

The problem

Pet owners had no structured way to find vets; clinics had no simple digital presence. The product needed to be a social platform first, with clinic management growing out of it.

02

Thinking before building

Requirements came directly from clients and the project manager, so before writing code I mapped the domain: users, pets, vets, clinics, appointments, records. The MySQL schema came out of that model — not the other way around.

03

Architecture

A clean split: React frontend talking to a Laravel REST API, with a MySQL database behind it. A separate mobile team consumed the same API — so endpoint contracts had to be designed for two clients, not one.

04

The hard parts

PDF medical reports: chose server-side headless-Chrome rendering so reports print pixel-perfect regardless of the client.
Medicine reminders: Laravel queued jobs and scheduled tasks, with Supervisor keeping the workers alive on Linux — reminders can't silently die in production.

05

Ownership

I don't just write the code — I deploy and administer the production stack on AWS EC2 (Ubuntu): server configuration, dependency management, queue workers, and troubleshooting when things break at 2am.

06

The outcome

The platform runs in production. I joined as a trainee and was promoted to a full contract within three months.
